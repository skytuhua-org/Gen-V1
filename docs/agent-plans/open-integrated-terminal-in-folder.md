## OBJECTIVE

A user looking at a project folder should not have to copy its path or type a shell-dependent directory change. From the current Project Files breadcrumb or from one of its listed folders, **Open terminal here** starts exactly one new Gen terminal, using the existing default shell and environment, at the selected directory in that Files view's working copy. The previous terminal, if any, continues as-is. A stale or unsafe selection must produce a useful error, not a shell at some other location. Success is a fresh, interactive terminal whose host-reported native spawn directory and shell working-directory check both match the selected folder, with no synthetic terminal input.

## DESIGN

### 1. Selection and wire contract

Add one optional directory-launch selection to the existing terminal create schema, parsed identically at the route and host boundary. A root launch from Files has an explicit empty relative path plus proof; omitting the object retains every old root-launch caller. Require caller-generated `terminalId` when the object is supplied. No public `command`, `program`, `args`, environment, absolute path or shell fields. Keep the existing body limit and response identity; use normal authenticated, CSRF-protected fetches.

```json
{
  "projectId": "project-a",
  "threadId": "thread-a",
  "terminalId": "test-terminal-1",
  "directory": { "path": "packages/demo app", "proof": "<opaque host proof>" }
}
```

Use forward-slash-separated, raw, case-preserved segments. Empty is allowed only as the root representation. Bound the path to 1,024 code units and 1,024 UTF-8 bytes, proof to 128 ASCII characters. Reject absolute, drive/UNC/device forms, backslashes, colons, empty interior segments, dot/parent segments, Git and guard-marker components case-insensitively, C0/DEL/C1 controls, bidi overrides/isolates and unpaired surrogates. Reject segment names with ambiguous Windows reserved/trailing-dot/space forms, never trim them into another path. Preserve ordinary spaces, apostrophes and Unicode. Treat percent signs literally, never URL-decode request JSON again. Resolve only against the server-selected admitted root; compare canonical containment as a path relation, not a string prefix. Raw names remain valid Files navigation even when unavailable for terminal launch.

Extend the listing response additively with optional `terminalDirectoryProof` for the current directory and for its individually eligible directory entries (not files). Derive under the guarded listing, checking an ordinary identity for the listed target; reuse the existing entry cap, no recursive walk and no separate client requests for icons. Use bounded parallel stats under the parent guard (start with eight workers), omit proofs for raced/unavailable children without failing the listing. Only request proofs when the surface can place an integrated terminal (e.g. optional strict `terminalLaunch=1` on the Files list route); default existing list cost/shape unchanged.

Issue compact host-signed proofs using a process-local random key, expiry (10 minutes) and a versioned, unambiguous tuple of owner, stable current binding stamp (project and optional workspace record identity and admitted root identity), exact relative path, and target filesystem identity. Use a constant-time MAC comparison over fixed-size decoded signatures; no raw absolute path, filesystem ID, key, or environment value crosses the wire or enters telemetry. Validate against current server observations, not client-supplied identity. Proof means “this eligible directory was listed”; it cannot authorize anything. Host restart and stale lists require fresh proofs; old clients ignore optional fields, new clients omit the action when server/list shape lacks support. A directory's identity is not inferred from its name, display label, cached root, or editable client state.

### 2. Host admission, native launch and idempotence

1. Parse owner, ID and strict selection before collecting environment. Validate the same project/thread/local admission as the existing interactive terminal and its canonical checkout. Snapshot the actual binding discriminator and root identity, not just pathname. T01 checks whether any applicable terminal trust ledger/policy now exists; use that policy as well as connected-root admission, rechecking current authority immediately before spawn. The baseline terminal path has no separate grant prompt. Do not reuse a different operation's trust receipt, bypass a gate or add auto-trust.
2. Reserve a host-local in-flight slot by ID for folder starts, tied to owner/binding and exact path/proof. Identical concurrent retries can join only after independent owner/binding admission; mismatched requests fail. Hold the reservation through awaits and cleanup. Preserve the existing capacity check immediately before creation; if native start can yield, count outstanding starts along with active PTYs and recheck duplicate/persisted IDs for both directory and legacy creates. Do not cache successful session objects outside the normal session table. A retry can receive the same live session after the proof deadline only with the original exact request and current same owner/binding; it is not a new spawn. Omitted or different proof is not a directory-session create retry.
3. After env resolution, acquire the existing directory custody for admitted root and target. Re-read current binding/trust in custody; check every intervening component, ordinary directory and identity, canonical containment and protected storage exclusions. Compare proof to the current observations and check expiry again. Finish the last in-process owner/trust/ID/capacity checks without yielding between that check and initiating native spawn. Hold custody until native process creation has consumed cwd. Windows node-pty 1.1.0 calls native ConPTY connect with cwd during agent construction; confirm on the installed path and with a controlled race at the native boundary. Reuse the Linux broker only where it proves custody through spawn; fail closed on a platform/filesystem with no verified primitive. No substitute based on realpath followed by an unguarded spawn. Release custody on every outcome; do not hold it for the PTY's lifetime or claim it sandboxes an interactive shell after startup.
4. Send the resolved native path only to node-pty's `cwd`; inherit the same shell, shell flags and environment policy. Install lifecycle listeners, publish the live session and existing durable used-ID record with the same cleanup guarantees as legacy start. Store only the launch discriminator and original selection fingerprint in memory for replay; don't add cwd, raw proof or environment to terminal records. Register ownership before acknowledging the start. If a failure can occur after native creation (guard loss, registration/receipt failure), stop or definitively account for that process before settling. Do not report “no terminal started” for unconfirmed termination, reuse an ambiguously consumed ID, or silently spawn a replacement. Preserve the existing owner-scoped Stop exception for cleanup after a binding change.
5. Stable in-scope error categories: invalid input via existing validation path; stale/expired/missing/replaced selection as proposed `TERMINAL_DIRECTORY_STALE`; nonlocal/wrong owner, linked/out-of-root and request mismatch as `CAPABILITY_DENIED`; unsupported safe launch as proposed `TERMINAL_DIRECTORY_UNAVAILABLE`. Preserve `PROJECT_NOT_CONNECTED`, `TERMINAL_CAPACITY`, `TERMINAL_ENDED` and stop-confirmation semantics. Route tests must assert the exact error envelope/status after checking the existing mapper. Redact native paths, proofs and shell/environment in outward error text; never use raw OS errors as user messages.

### 3. Placement, attachment and recovery

- App-level launch coordinator, not Project Files or an agent command, captures effective local owner, source surface/placement destination, folder generation, and a fresh ID on explicit activation. Recheck after auth, host acknowledgment and before choosing/committing placement. Allow one pending launch per Files surface; snapshot the target and do not substitute the subsequently selected thread or folder. Validate response ID/project/thread; no focus or successful placement on a late or mismatched response.
- Launch only when a destination can visibly place a distinct terminal. In Custom/split add a terminal view to the owning pane with an explicit attach reference. In canvas add and select a fresh terminal panel using the current workspace receipt mechanism. For the legacy main Files sidebar, use the owning main workspace canvas with explicit binding (and reveal it through the existing workspace navigation), rather than replacing the legacy default Terminal slot or selecting a terminal for the active global thread. T01 must prove a place-and-reveal path for each enabled surface, including a connected project without a thread. If placement is not supported for a detached-only view, omit launch there; reattaching a terminal that already exists stays supported. Preserve the Files state and any previous terminal reference in all routes.
- Carry persisted `terminalId` and a proposed `terminalAttachOnly: true` flag on the local terminal binding **only** for an acknowledged launch. Enforce valid pairing in strict binding/admission; absent means legacy start semantics. Never store folder/proof in layout or profiles. Keep explicit attach branch separate from ID generation, reject duplicate presentation of the same receipt except reveal/reparent, and verify split/canvas/native and workspace/profile paths retain the attach-only bit. Disable this launch path with unsupported old host/schema; do not coerce an unknown attach branch into legacy auto-create.
- `TerminalBody` for attach-only initializes the same xterm, reads exactly that ID via authenticated GET, matches its owner and begins existing poll/fit/input/stop flows only after a valid read. No POST create on mount, resize, retry, restore or native reparent. Interrupted read can retry GET; ended/unknown IDs do not auto-spawn. A separately clicked **New terminal** retains existing root-start semantics and does not reuse the directory proof or ID. The normal root-start path and integrated program endpoints are untouched.
- No automatic retries on ambiguous create or placement. Keep the original request only in the in-memory coordinator for explicit user retry (same ID, proof and owner); preserve the ID when reattaching, never mint a new ID until a different explicit selection after a definitive failure. On ambiguous placement, reconcile by stable view/panel ID and receipt/readback before retry, cleanup or focusing. If create succeeds but origin becomes stale or placement is definitively refused, stop the exact unplaced session with captured owner and confirm exit; do not terminate one already placed by an accepted receipt. Continue reconciliation after route unmount; no late work uses the newly active surface. If cleanup is unconfirmed expose an owner-scoped recovery notice and a retry of reconciliation/stop; don't start another as recovery. Host restart ends old IDs, and layout reload may only read them. T01/T06 exercise whether a renderer loss before a placement receipt leaves an inaccessible process; if so, require host-managed bounded unplaced-start recovery tied to the same ID before enabling, not a bare timer that can kill a placed terminal.

### 5. Compatibility and rollback

No schema migration for existing sessions. Read-only fields in Files are additive/opt-in; folder requests are reject-only on an old host. Keep legacy open (including its main shell behavior), attach-only reads and used-ID protections distinct. Control the new affordance with the existing capability/availability seam; if reverting product entry points, keep attach-only schema/read semantics until existing saved references are drained or safely marked ended. Never convert these references into root auto-starts; no branch/profile repair by mutating project roots. If a genuine scope issue is found (e.g. unsupported native custody), leave the feature off for that platform and record it; don't weaken validation to ship.
