## OBJECTIVE

The optional global budget is not configured by production. Admission checks the three-live and per-task counts before awaited authority/proof validation, without rechecking them before storing the work, so concurrent admissions can exceed those counts. Token/time ledger checks occur after that await and synchronously before Store.command; a same-event-loop global-budget race is not established by this source. Requested maxima are reserved, but runtime token/time enforcement or usage settlement is absent; failed/cancelled reservations contribute lifetime use conservatively. Resume checks token limit but omits the corresponding global time check. Existing budget tests are serial and use injected caps.

Deliver enforce child token and time budgets atomically across admission and resume through the retained implementation. Success means the exact original requirements mapped below are observable from the supported host path, the named failure cases have deterministic regression evidence, and unsupported capabilities remain unavailable. Contract definitions, test-only injection and historical merged PRs are evidence of retained work, not current live acceptance.

## DESIGN

Make budget policy explicit in the host and reserve tokens/time plus capacity atomically with admission after asynchronous proof validation and a final current-owner recheck. Use durable reservation IDs and idempotent transitions so replay cannot consume twice. Tie real adapter usage and monotonic elapsed-time events to each reservation; stop when the accepted budget is exhausted and retain failed/cancelled consumption. If usage cannot be observed, conservative reservation remains charged and capability availability explains the limitation. Resume must reserve both dimensions before dispatch. Do not add recursive spawn or exceed three initial live planning slots.

### Concrete implementation and integration boundary

Recheck live/per-task capacity after awaited proof validation, atomically with the durable admission/reservation, and make replay lookup precede capacity rejection. Preserve currently synchronous post-await token/time checks; centralize them transactionally only as required by the accepted Store ownership contract. Add dual-dimension resume reservation and adapter budget/usage enforcement. Integrate confirmed cleanup semantics from PR1866 so unconfirmed native children retain capacity. Persist charged/remaining budget and exhaustion reason.

Current agent rows show reserved, consumed/unknown and remaining budget consistently. Budget exhaustion is a specific failure/blocked reason; resumed work shows the new reservation without erasing previous charged work. No optimistic released capacity before teardown proof.

### Failure, persistence, migration and rollback

Validate owner/source/epoch/revision immediately before authority-bearing effects and again when accepting asynchronous results. Preserve uncertain outcomes as explicit unknown/conflict/partial states; retry only after authoritative reconciliation. Writes must be either idempotently replayable from their durable receipt or require a new exact preview/approval. A UI acknowledgment is not an effect receipt. Missing proof remains unavailable, with the successful read-only path preserved.

New records require an explicit schema version, compatibility test against the retained format, and an owner-approved migration plan before T03. Rollback disables new admission at the existing host flag/capability boundary, retains all receipts, journals, blobs and dirty workspaces, and closes only confirmed-owned resources. It never rewrites user bytes or replays an unresolved input automatically. Do not remove historical evidence; label its source and acceptance limit.
