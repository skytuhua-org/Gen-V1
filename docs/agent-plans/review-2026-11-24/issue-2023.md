## OBJECTIVE

No production debugAdapterFor is installed, so sessions are unavailable by default. When injected, launch consumes an approval and checks a backend proof. Later effect calls use only session owner and command membership, without a fresh effect admission or current proof check. inspect also allows STOPPED, and threads/scopes are not bounded like frames/variables. dispose deletes sessions after termination failure. Owner is project hash, not full epoch. M06 debug fingerprints are derived from command/adapter labels rather than the actual source/environment.

Deliver revalidate debugger effect authority and retain native session custody through the retained implementation. Success means the exact original requirements mapped below are observable from the supported host path, the named failure cases have deterministic regression evidence, and unsupported capabilities remain unavailable. Contract definitions, test-only injection and historical merged PRs are evidence of retained work, not current live acceptance.

Replace guessed advisory fingerprints with an accepted source/recipe environment record. Register a production adapter only when its approved installed identity and platform proof exist.

Expose a supported shared review control only after the host proves availability. Inspect, Continue, Step and Stop each reflect the host capability and reason; a missing backend is unavailable. Show actual state and cleanup failure. No shell fallback, downloads or project plugin enablement.

### Failure, persistence, migration and rollback

Validate owner/source/epoch/revision immediately before authority-bearing effects and again when accepting asynchronous results. Preserve uncertain outcomes as explicit unknown/conflict/partial states; retry only after authoritative reconciliation. Writes must be either idempotently replayable from their durable receipt or require a new exact preview/approval. A UI acknowledgment is not an effect receipt. Missing proof remains unavailable, with the successful read-only path preserved.

New records require an explicit schema version, compatibility test against the retained format, and an owner-approved migration plan before T03. Rollback disables new admission at the existing host flag/capability boundary, retains all receipts, journals, blobs and dirty workspaces, and closes only confirmed-owned resources. It never rewrites user bytes or replays an unresolved input automatically. Do not remove historical evidence; label its source and acceptance limit.
