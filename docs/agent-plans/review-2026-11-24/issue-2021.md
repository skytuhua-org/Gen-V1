## OBJECTIVE

The parser and registry enforce inert partial arguments, open-count and byte caps. The route scopes previews to a project hash, seals with beforeDigestFor returning null, accepts client-supplied settle outcomes, and is not connected to run cancellation or a real completed edit. The display component only lists preview states; it has no production caller or approval control. locateAnchor/verifyEditPreimage are helpers without the existing file.replace dispatch join. A mock registry PASS does not prove a preimage-bound user approval flow.

Deliver connect inert edit previews to exact preimages and the supported approval flow through the retained implementation. Success means the exact original requirements mapped below are observable from the supported host path, the named failure cases have deterministic regression evidence, and unsupported capabilities remain unavailable. Contract definitions, test-only injection and historical merged PRs are evidence of retained work, not current live acceptance.

## REQUIREMENTS

### Authoritative original requirements for this focused gap

**M07-C02.** EditPreviewV1: previewId, owner, schemaDigest, finalArgumentsDigest|null, targetFiles[{path,identity,beforeDigest,proposedDigest}], state STREAMING_UNAPPLIED|READY_UNAPPLIED|INVALID|APPLIED|CONFLICT. No preview frame authorizes a write.

**M07-S06.** Implement precise edit preconditions using existing host edit operations and before hashes. A short anchor or hashline label is only a locator, not a collision-resistant authorization. Reject ambiguous matches instead of fuzzy rewriting arbitrary code.

**M07-S07.** If a provider exposes incremental tool arguments, display a STREAMING_UNAPPLIED diff preview through a pure parser. Do not execute partially parsed commands. Bound open previews to 8 per run, 256 KiB aggregate, and discard on cancellation. Final arguments must match the preview digest; otherwise rebuild a new preview before approval.

**M07-U02.** Streamed diffs carry a persistent Not applied label. Approve becomes available only after complete validated arguments and a current preimage. A changed preview invalidates prior approval.

**M07-T02.** Unicode positions, external file URIs, malicious server edits, ambiguous anchors and unsupported resource operations are refused or normalized correctly.

**M07-T03.** Partial streamed edit cannot write; final argument mismatch invalidates preview and approval. Oversized previews are bounded.

**M07-G02.** Host-owned flags: coding.intelligenceV1, coding.renameV1, coding.debuggerV1. Register only these keys in the shared finite registry; default false. Do not add them to strict UI preferences or allow agents/plugins to enable them. Each risky sub-capability needs its own proof; do not use one successful core test to unlock all flags.

**M07-G03.** Rollback: Disable adapters, close owned servers and retain edit recovery journals. Do not revert user code automatically during feature rollback; resolve pending per-file recovery explicitly.

## DESIGN

Use the existing approved file operation as the sole write boundary. Scope previews to the complete owner/run epoch and tool invocation; snapshot targets through approved bound reads at sealing. Validate both exact final argument digest and current preimage immediately before action commitment, then let the existing operation engine perform the write. Only its committed receipt may settle APPLIED. Changed arguments, target bytes or owner invalidate approval. Provider capability must explicitly expose incremental arguments; otherwise show only the final preview. Keep 8 open/256 KiB per run and release all buffers on cancellation.

### Concrete implementation and integration boundary

Replace project-only ownership and null preimages in code-intelligence-routes with the accepted service-owned operation identity and bound-read callback. Remove client authority to declare APPLIED. Connect validateFinal and current-preimage checks to the existing exact approval action commitment. Hook discardOwner to real run cancellation and failure; no duplicate write executor.

Add the preview to the agreed shared Changes/Files host after the explicit current-surface decision. Keep Not applied visible through streaming and readiness. Show before/after content only from complete parsed targets. Enable confirmation only for current preimages and valid final arguments; approval mismatch resets confirmation. Include loading, invalid, conflict and unavailable states, with keyboard focus on actionable confirmation.

### Failure, persistence, migration and rollback

Validate owner/source/epoch/revision immediately before authority-bearing effects and again when accepting asynchronous results. Preserve uncertain outcomes as explicit unknown/conflict/partial states; retry only after authoritative reconciliation. Writes must be either idempotently replayable from their durable receipt or require a new exact preview/approval. A UI acknowledgment is not an effect receipt. Missing proof remains unavailable, with the successful read-only path preserved.

New records require an explicit schema version, compatibility test against the retained format, and an owner-approved migration plan before T03. Rollback disables new admission at the existing host flag/capability boundary, retains all receipts, journals, blobs and dirty workspaces, and closes only confirmed-owned resources. It never rewrites user bytes or replays an unresolved input automatically. Do not remove historical evidence; label its source and acceptance limit.
