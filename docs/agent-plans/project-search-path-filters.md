## OBJECTIVE

Users searching a project for a file name or phrase need to narrow results without changing folders, editing repo configuration, or sifting through tests and generated files. In an environment where Project Search is available, entering **Include paths** `src/**/*.ts` and **Exclude paths** `**/*.test.ts` should show filename and text matches only in matching non-test TypeScript files under `src/`. Clearing both fields and re-running the same query must reproduce the unfiltered result, ordering, and scan disclosures on unchanged fixtures.

## DESIGN

### Grammar and request contract

Add optional `include` and `exclude` **string** fields to the strict request schema and typed adapter. Share a browser-safe validator/normalizer from the contract layer (no Node imports); the host validates independently of the UI. For a future authorized HTTP adapter, use exactly one `URLSearchParams` entry per canonical nonempty field on every page; do not concatenate unescaped input. No fields are added to the response. Existing strict decode and auth behavior stays intact. Example on the isolated route: `GET /api/projects/p/search?q=needle&include=src%2F**%2F*.ts&exclude=**%2F*.test.ts&limit=1`; continuation adds `cursor` to the same criteria.

- Reject invalid Unicode and ASCII control characters (code points 0–31 and 127) before trimming. Limit each raw value to 512 UTF-8 bytes and each trimmed nonempty value to 200 Unicode code points and 32 nonempty slash-separated segments. Trim outer whitespace only; canonical blank becomes absent. Reject leading/trailing/doubled slash, segments exactly `.` or `..`, backslash, colon, and unsupported list/class/expansion markers `, [] {}`. Other Unicode characters and interior spaces are literal; do not case-fold, Unicode-normalize, or decode percent sequences a second time. Invalid input is not silently converted to blank or truncated.
- A segment `**` alone matches zero or more complete segments. Other segments allow `*` for zero or more non-slash code points and `?` for exactly one non-slash code point. Reject consecutive stars except a segment exactly `**`. All matching is from root to full path; a pattern with no slash matches a root-level file only, unless its only segment is `**`. Dot-prefixed names are matched like ordinary names **after** baseline eligibility checks; patterns never override those checks.
- `src/**/*.ts` matches `src/needle.ts` and `src/lib/needle.ts`, not `other/src/needle.ts` or `src/Needle.TS`. `*.ts` does not match `src/needle.ts`; use `**/*.ts`. `src` does not select descendants; use `src/**`. `src/?.ts` matches `src/😀.ts`, not `src/ab.ts`. `**/*.test.ts` matches test files at root and at any depth.
- Reject semantically invalid filters through the existing `400 INVALID_INPUT` path with no-store, before admission or guard acquisition. Do not echo raw patterns or absolute paths in error responses, logs or telemetry. UI: identify the affected field and show a stable plain-language grammar/limit error; do not reveal host internals. Keep null, arrays, duplicates (including encoded aliases), malformed percent sequences and unknown keys invalid. Missing and canonical blank are equivalent for snapshot comparison.

### Host and request lifecycle

1. Validate at `search` (including direct callers), then compile each nonempty pattern once on the initial scan. Use iterative segment-level dynamic programming: ordinary pattern segments advance one candidate segment; `**` advances zero or more segments with reuse of already computed states. Within a segment use rolling code-point DP for literals, `?` and `*`. Bound work by pattern × candidate length and memory by rolling rows; use the existing 1,024-byte admitted-path bound. No shell, regex constructed from user text, filesystem join from a glob, recursion/backtracking on patterns, or new dependency.
2. Leave traversal and directory admission unchanged. In the file branch after safe live-path/regular-single-link checks and counting the ordinary file toward the existing file cap, but before size/byte admission or `read`, evaluate `(!include || matches(include, child)) && (!exclude || !matches(exclude, child))` with scan cancellation/deadline checks before and after. The matcher sees `child`, not a resolved path. Never prune directories in v1: unmatched parent names do not exclude matching descendants, and traversal limits and discovery errors remain intact.
3. Files skipped by user criteria consume no content-read bytes and produce neither hits nor user-filter issue rows. Preserve pre-existing hard-exclusion and traversal issue checks and disclosures; size/binary issues are assessed only for eligible content. The 10,000 ordinary-file cap, 32 MiB read cap, 1 MiB per eligible file, 1,000 match cap, two-second deadline, snapshot/page limits, sort order and partial-result statuses remain. Filtering does not imply that the whole project was searched; keep incomplete warnings even if zero hits.
4. Add normalized include/exclude to the in-memory `Snapshot` identity compared alongside folded query, limit, project/thread and re-admitted binding. A different valid pair returns `INVALID_CURSOR`; retrying the same normalized pair preserves immutable pages. Keep cursor signature, handle, TTL (five minutes), snapshot count, re-admission, cancellation, response shape and byte accounting intact. No durable state or raw filter text in returned cursors.
5. In the adapter and result reader, pass the same canonical pair for first page, Load more, Retry and refresh. Key the mounted results, `useFilesRead` and read callback dependencies by owner IDs, committed text and both canonical values. A real criteria change remounts results, clears cached page and cursor and aborts the old reader. Whitespace-equivalent reapply is a no-op. Same-key refresh and retry retain current accepted rows per baseline; Refresh/Restart reset pagination, and a late or aborted page never appends to the new key. Keep the preview independent: filtering does not close a file already open or change permission to open it; only matching visible result keys can have current-row styling.

### Visual, interaction and motion specification

- Place **Filters** immediately under **Search project** and above list/status. Default collapsed; native button with a 14 px decorative chevron, minimum existing 32 px button height, and `aria-expanded`/`aria-controls`. In the same row show **1 active** / **2 active** only for applied filters, and **Unapplied changes** when drafts differ (use text, not color alone). Keep all content inside the left content column; no popover or overlay. No Filters row in Folder, Granted Files, or unavailable Project mode.
- Expanded layout, in order: **Include paths** (placeholder `src/**/*.ts`), **Exclude paths** (placeholder `**/*.test.ts`), help **One glob per field, relative to this project. Exclude wins.** plus a short `*`/`**`/`?` hint, then **Apply filters** and **Clear filters**. Use visible 12 px labels and existing .files-filter input styling, Files inset, 8 px gaps, 6 px input radius, surface/border/text/muted tokens and existing focus ring. Two equal flexible columns above the 560 px container breakpoint and one column at/below it; wrap hint, errors and actions without spilling at 375 px. Use muted status text only when contrast is sufficient in both themes; errors use existing Files error treatment, with text and `aria-invalid`/`aria-describedby`.
- Drafts are local to the mounted Project surface. Apply (including Enter in a non-composing filter input) validates both fields and atomically commits the pair, with the panel left open. While composing, do not use Enter to submit. Pending draft edits do not change the applied result set. Invalid Apply sends no request, retains prior applied criteria, expands/stays open and focuses the first invalid input. Clear resets drafts, validation and committed filters at once, leaves text alone, and focuses Include; keep controls stable for focus. Applying before typing text may save criteria for the next text search but does not scan. Preserve the text box’s 300 ms debounce/IME and Escape-to-clear-text; it must not clear filters. No extra debounce for explicit Apply/Clear.
- Tab order: search box → disclosure → visible form controls in DOM order (include, exclude, apply, clear) → results and pagination. Enter/Space on the disclosure uses native button behavior. Closing with the button leaves focus there; Escape in the filter region when not composing collapses and returns focus to the button without applying or discarding drafts. Closed controls are hidden, unfocusable and out of the accessibility tree. Owner or scope remount starts with blank drafts, no filters and collapsed disclosure. Keep existing result arrow/Escape behavior and polite search announcements; name applied filters as a scope, not an access change.
- Motion: opening lays out the panel immediately, then animate only the revealed inner content from opacity 0 to 1 and vertical offset −4 px to 0 using `--ui-motion-status` (160 ms) and `--ui-ease-enter`. Rotate chevron from right to down over the same duration. Close hides controls immediately and returns the chevron with `--ui-motion-remove` (140 ms); no height tween, exit ghost, delayed focus, result-list animation or motion on Apply/Retry/Refresh. Under `prefers-reduced-motion: reduce`, all disclosure visual changes are immediate, with identical focus and semantics.
- With applied filters and a complete empty response use **No results match these path filters.** and **Try a different search or clear the filters.** Keep the baseline incomplete warning if scanning stops early; do not call an incomplete scan complete or make a filtered zero state a failure. Validation is local to fields; transport failures use existing Retry/Restart, never auto-fall back to an unfiltered request.

### Compatibility, rollout and rollback

Old callers omitting both keys get existing behavior and unchanged responses. Land contract, host, adapter and UI together once implementation is authorized; do not expose a filter UI to a backend that cannot accept it. At this baseline keep the isolated production fallback unchanged. If Project Search is later enabled via separate authorized work, require a same-build host/client integration check (including authenticated registration and encoding) before marketing or enabling the filter feature. Revert the coordinated feature change to roll back; there is no data migration or settings to clean up. Restart invalidates ephemeral cursors by design; the existing Restart search action recovers.
