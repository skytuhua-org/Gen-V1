## Objective

After a commit, Changes can still show uncommitted work, recorded diffs, and file checkpoints, but none lets a user answer “what went into that commit?” without leaving Gen. Add a read-only **Git history** tab. A user should be able to open Changes, see the latest 50 commits from that working copy, select one and inspect its changed files and patch, and copy the full SHA without opening a terminal, signing into GitHub, or modifying the repository.

## Technical design

**Read flow.** The tab uses authenticated same-origin GETs (server and client no-store) under `/api/projects/:projectId/git/history`, with the same optional `threadId` as Current. Proposed routes:

| Request | Response |
| --- | --- |
| `GET /git/history?cursor=…` (omit cursor for first page) | `{snapshotId, branch, headOid, upstreamRef, commits, nextCursor}`. Branch and upstreamRef are nullable; unborn repository returns null head, no rows and no cursor. Each row: `{oid, subject, author, authoredAt, filesChanged, pushState}`; count is exact or null if not known within limits; pushState is `unpushed\|notMarked\|unknown`. No commit message body or author email. |
| `GET /git/history/commit?snapshotId=…&oid=…` | `{comparisonId, oid, parentOid, basis, files, filesTruncated}` with basis `first-parent\|root`, existing ComparisonFile fields and no checks/actions. |
| `GET /git/history/file?comparisonId=…&path=…` | File identity, existing patch state/text/reason conventions, and the same commit comparison identity. Text is null for binary, unavailable or truncated. Do not change the meaning or shape of the existing comparison routes. |

**Snapshot and paging.** Resolve the full commit OID and symbolic HEAD via fixed Git args inside the existing attested, read-only operation. Distinguish unborn from Git errors: only a symbolic branch with no tip is empty; a corrupt or missing object is unavailable. Accept only canonical lowercase full OIDs supported by the existing storage (SHA-1 at this baseline), strict query schemas, bounded tokens and repo-relative paths. Route parameter values must never be used as directory paths. Keep bounded, in-memory owner-scoped snapshots using the comparison cache pattern (start with eight per owner, 64 globally, 15-minute inactivity expiry, and a per-snapshot ceiling of 1,000 rows; evict least-recently-used). Capture project/thread plus attested binding, HEAD and ref OIDs, and keep paging offset server-side in an opaque idempotent cursor. Cache commit-detail authorization only for rows the snapshot actually served; the membership of a commit in the upstream comparison does not authorize it. Recheck identity, tip/branch and tracking ref at the next request; on move/expiry refuse continuation and offer Refresh rather than mixing snapshots. No per-row ancestry subprocess or patch prefetch.

**History query.** Use `git log --topo-order --max-count=51 --skip=<serverOffset> -z --format=...` against the pinned full OID, with `--end-of-options` before the OID and `--` after it. The extra row is lookahead only. Frame OID, author, ISO author timestamp and subject using NUL separators; parse bounded fields, not newline/tab-delimited subjects or paths. Batch the file counts for the visible page using Git's NUL-delimited name/status or numstat format; request first-parent merge diffs, root diffs, rename detection and no external diff/textconv. Verify the exact combined Git output framing on the supported Git versions in T02; match counts to full OID, count a rename as one, and never infer counts from patch lines or omit binary paths. If counts alone exceed the existing Git byte/time cap, return the metadata page with unknown counts and still allow bounded detail reads. A log that cannot be enumerated safely returns a typed error, not fabricated empty history. Bound subject/author display and sanitize control characters without rewriting SHA or retained patch content.

**Unpushed semantics.** Use a safely resolved local remote-tracking upstream in an attested view when available. Where the view has stripped tracking configuration, use the exact same-branch `refs/remotes/origin/<branch>` only when it exists; label that exact ref as the comparison basis and do not claim it is the configured upstream. Use no fallback for detached HEAD, a known different configured upstream that cannot be read, or a local-only upstream. Resolve the ref to an OID under the same boundary; never open the live config outside the guard or fetch to create a ref. Compute membership with one bounded positive-range walk per snapshot: `git rev-list --max-count=10001 <headOid> ^<upstreamOid> --`, both OIDs resolved by the host. Retain the bounded OID set for the snapshot so later pages do not repeat the walk. An emitted row is Unpushed; an absent row is unmarked only after a complete walk. When the process hits its time/output cap, use unknown for the affected page. Validate against `git merge-base --is-ancestor` as the test oracle for merged and diverged graphs. A capped traversal that cannot prove absence must report unknown, never tag common ancestors as unpushed. Display “Compared with local origin/…; may be out of date” (or the resolved ref) in the header. When no basis is available show “Push status unavailable”.

**Committed comparison and patch.** Inside the same project lock and authorized snapshot, require the selected commit to have been served to this owner. Determine parents from the validated commit; for deep or shallow imports with a recorded but unavailable first parent, return a typed unavailable result rather than treating it as a root. Use a root-aware, read-only tree comparison without writing the empty-tree object; first-parent diff for every merge, not combined diff and not diff against Current. Use fixed Git args: no color, external diff, or textconv, with bounded rename detection, `--` and literal pathspecs for both sides of a verified rename. Retain only the selected comparison's bounded file membership and enforce it before spawning Git for a patch. Treat unusual paths using existing safe display/path rules; an unsupported path can be listed with no patch, never resolved as a host file. Use existing caps (1,000 file entries, 256 KiB patch, `nativeGit` process/output ceiling); count or list truncation must be explicit, no partial patch. Distinguish empty commit, mode-only text or notice, unsupported/binary, limit, and unavailable. Never read from the current index or working files to construct a committed patch. Preserve the Git guard and environment; do not use a shell, arbitrary config, replace refs, hooks, a new auth path, or direct filesystem access from the browser. API messages should not contain absolute host paths, stderr, or checkout metadata beyond the declared response. Cancel pending browser requests and fence late results; thread any host cancellation through existing safe process/guard owners only, with a documented bounded operation if the route lifecycle cannot safely abort host work.

**Visual and interaction design.** Keep the existing Changes tab strip and add Git history as its fourth tab when the local Changes surface is available; keep checkpoint History named as-is and retain Current/Recorded state. Match toolbar height, existing colors/surfaces, focus ring, spacing and file-name typography. Header: branch (or “Detached HEAD” plus short OID), comparison-basis note, and Refresh history. List: compact rows with two lines, subject first (wrap to two lines at narrow widths), author/time/files on the second with a neutral outlined “Unpushed” badge. Keep the full subject accessible. Selected row has a tinted background and visible accent marker; use text plus selection semantics, not color alone. Show list and detail side by side only at a container width of at least 720 px; list near one third width with a minimum of 240 px. Below that replace the list with detail after selection and show **Back to commits**. Detail header: subject, full selectable monospace SHA, Copy SHA icon/button with accessible label, and a first-parent/root label. Show file buttons and statuses above a single active patch. Use the shared unified patch treatment from checkpoint/recorded diff surfaces via a narrowly extracted presentational component if no already suitable comparison viewer is found; checkpoint keeps its existing trimmed presentation, committed patch stays verbatim. Respect existing palette and expansion preferences (`diffDefaultExpanded` controls opening the first file on selection; other file activations open immediately); no pair layout or whitespace suppression on unified patches. Scroll the patch locally, not the whole Changes layout. No new theme token or independent diff engine.

Calculate relative time with `Intl.RelativeTimeFormat`: under one minute “just now”, then whole minutes, hours, days, months and years; do not imply that a future author timestamp happened in the past. Use the user’s locale and refresh displayed ages while the tab is active. Use existing tab Arrow/Home/End behavior and normal button Tab/Enter/Space behavior for commit/file picks. Announce page loads, count appended and failure via a polite status region; leave focus on Load more unless it disappears at end, then focus the last added row or the list heading if no rows were added. Keep row focus on wide selection; move focus to the detail heading on narrow selection and restore it to the originating row on Back. Retry at the failing boundary (page, commit or file); keep existing rows on pagination failure and don't show a stale patch under a new selection. Distinct copy: “No commits yet”, “No files changed in this commit”, “Commit history unavailable”, “History changed. Refresh history to continue.”, “Binary file — no text diff”, “Diff is too large to display.” Use a 120 ms opacity transition on newly selected, loaded detail and existing button hover/focus feedback. No height, position, scroll or list entrance animation. Under reduced motion, transition instantly. The source tabs, selection, focus, and loading state exist without animation.

**Rollout and rollback.** No schema migration, disk cache, background poller, new dependencies, or remote integration. Additive read-only endpoints; gate the tab on local authority and connected project using the existing Changes/binding contract, not checkpoint capability. A disconnected or unsupported project retains existing views; a supported connection with unavailable history gets a scoped error. If reverting, remove the Git history slot and its endpoints together; existing Changes routes and data stay untouched.
