## OBJECTIVE

A developer reading source in Files has to switch to another tool to find the commit behind a line. Add an explicit, read-only lookup in the connected project's plain-text preview. A user can select one visible line, request its attribution, and copy the full commit SHA without leaving the pane. On the two-commit fixture in VALIDATION, a line left untouched by the second commit must report the first author and SHA, while the edited line must report the second. A result must never describe a different line, file, checkout, or unsaved version of the text.

## DESIGN

### Preview proof and HTTP contract

1. Extend the existing project `/file` response with additive `lineAttribution`: either `{kind: "eligible", previewProof, lineCount}` or `{kind: "unavailable", reason}`. Here “eligible” means text shape only, not verified Git status. Compute it from the already-guarded bytes; do not run Git, stat Git metadata, hash re-encoded text, or change existing preview behavior. If an older host omits the field, hide the control. A rejected `/file` read (e.g. over its existing 1 MiB limit) still uses the normal Files error and offers no lookup.
2. Text limits for attribution: at most 512 KiB actual bytes and 20,000 logical lines; nonempty, fatal UTF-8 validation and no NUL or lone CR. Preserve a UTF-8 BOM in the display/read identity; do not normalize whitespace, newlines or Unicode. Split on LF, with CRLF a single terminator; no phantom line after trailing LF, but real empty lines count (e.g. LF LF = two empty lines). Accept no-final-newline files. Keep the previous preview for unsupported content. Share a pure line policy between server and preview tests. Refuse on disagreement between the host's count and browser's source-line model.
3. Use a versioned, fixed-length HMAC proof minted in process (random secret, no logging or storage), over an unambiguous tuple: project ID, thread ID or null, workspace ID or null, admitted root identity, file identity observed under guard, canonical relative path and raw SHA-256. Obtain file identity from the guarded read's handle or verified guard entry; do not trust an adjacent standalone stat. Revalidate using constant-time equality after reconstructing it from the current read. Compose a pure helper for the existing guarded project file read used by both endpoints to avoid divergent containment. Proof authorizes nothing by itself; compare only after resolving and authorizing the requested owner. Restart or a different identity invalidates it and asks for a preview refresh. Neither the proof nor raw identities belong in logs or telemetry.
4. Add `POST /api/projects/:projectId/file/line-attribution` (read-only, POST to keep digest/proof and path out of the query). Register under the existing server middleware, with a strict JSON body limit of 8 KiB and no-store on success and errors. Request shape: `{threadId?: string, path: string, previewSha256: string, previewProof: string, line: number}`. Use the existing identifier bounds; SHA-256 = 64 lower-case hex; proof = versioned base64url HMAC format; line = integer 1–20,000, no coercion. Reject unknown keys, including any revision/authority/root fields. Use `authenticated`, same-origin credentials, CSRF header and no-store; validate responses with the shared schema.
5. Proposed discriminated response: `{kind:"attributed", sha: string, author: string, authorDateUtc: string, subject: string}` or `{kind:"unavailable", reason: enum}`. Full SHA is 40 lowercase hex for the repository's admitted SHA-1 Git format; UI derives its first 8 characters. Date is author epoch seconds converted to validated ISO UTC; do not infer committer or use blame date relative to now. Access/input errors remain non-success HTTP responses with safe contract error codes; React maps code to approved copy rather than rendering messages from the command. No echoed context/identity required: each promise is fenced by its initiating request. Bound name to 120 code points, summary to 240; remove C0/C1 controls and bidi overrides, replace absent/blank author/subject with “Unknown author” / “No commit subject”; use React text nodes and isolated bidi for names/subjects. Validate epoch, SHA and line, never fabricate a result on malformed output.

### Guarded Git read and race handling

1. Resolve via `ProjectTools.binding`; check controller/deadline before entering the existing per-project exclusive path and again on entry. Allow at most one admitted attribution operation per project at a time, returning `busy` to other requests while the work/cleanup is outstanding. Reject missing binding, company/delegate/side/mismatched thread and wrong proof before Git. Paths are exact, slash-separated, worktree-relative, validated with the existing bound-file containment plus rejection of empty/dot/parent segments, backslashes, colon, NUL/control characters, case-insensitive Git metadata segments or guard markers, and links/reparse points/non-regular files. Canonicalize to the admitted exact relative path; never silently rewrite case, Unicode or separators. Resolve and recheck source and root under guard; no widening symlink/path grants to support a filename.
2. Reuse the `withGitOperation` read selection, extending only as needed to accept the request signal and an explicit attribution policy. Managed: Store-attested private family with guarded worktree. Legacy: existing guarded sanitized view/import path (never invoke the user's .git/config); keep custody of the source metadata capture until the result is accepted. Existing legacy capture doesn't project shallow metadata: explicitly decline a shallow source there before relying on a copied view. For managed metadata decline if shallow is detected by Git. Missing/corrupt objects, unsupported object formats or repository configuration, and lost guards are non-results; no fallback or ref/network resolution. Reuse existing bounds on legacy capture, object copy and source projection. Do not redesign Git import as part of v1.
3. Inside the guard, pin a verified local `HEAD^{commit}` to its full OID. Use only that OID to look up a single exact tree entry and attribute a line. For example, invoke global `--literal-pathspecs` and `ls-tree -z --full-tree <oid> -- <path>`; accept one exact path, type blob and mode 100644 or 100755 only. No entry means `untracked` even if staged; do not consult index or attempt rename resolution on a missing path. Check raw blob size with `cat-file -s <blob-oid>` before reading. Read `cat-file blob <blob-oid>` with a bounded raw-byte stdout path under the same runner policy (no text decoder, transformations, shell, filters, redirects, or unbounded collection). Compare raw length and bytes with the guarded preview read, not status, dates, timestamps, a Git hash computed from converted text, or a normalized decoder string. Preserve existing process runner callers and timeout/output classifications; add a scoped opt-in raw mode or sibling sharing the spawn/abort policy in the existing boundary. Test exact Buffer semantics on CRLF, BOM, invalid UTF-8, NUL, and no terminal LF.
4. Only after equality and line bounds, run `git --literal-pathspecs blame --root --line-porcelain --encoding=UTF-8 --no-textconv --ignore-revs-file "" -L N,N <pinned-oid> -- <canonical-path>` through guarded native Git (prefix existing no pager, no replacement objects, no executable filters, no prompts or lazy fetch; additionally hard-disable protocols for this read). This is an argv array; empty ignore-revs-file argument is one empty string, not shell syntax. Do not disambiguate short SHA by another lookup or request author data from a service. Accept one result header, matching final line and group count 1, one tab-prefixed source record, and valid author-time. Parse only name/time/summary; discard source record, email, and other metadata. Reject truncated/malformed data and verify a fixture for boundary/root commits without history invention. Use raw byte comparison in step 3, not the porcelain source text, as proof.
5. Before success: re-resolve owner and active checkout, re-read guarded source identity and bytes, verify the original proof, and confirm HEAD still equals the pin. Managed: re-resolve HEAD inside the family guard before exit. Legacy: confirm the source HEAD/ref/packed-refs custody against the capture, not just the immutable projected HEAD; verify guarded entries still match and treat substitutions or ref changes as stale. Validate at guard completion; no success if any guard reports loss even after Git returned. If nested guards conflict on Windows, pass through the existing guarded file entry/read handle, or do equivalent two guarded reads and explicit identity comparison; no unguarded reopen. If the source changes after acceptance, the result remains about the accepted preview snapshot, not about a live file. Future lookups and preview refresh revalidate instead of polling.
6. Enforce an 8-second request budget end to end (including waiting for the project queue, import and Git); cap porcelain output at 1 MiB and raw blob stdout at 512 KiB; bound stderr independently. Compose disconnect, host shutdown, deadline and guard-abort signals using the route pattern from Project Search. Cancel process trees; ensure aborted queued callbacks never start Git and that capacity is held until cleanup finishes. If slow guard initialization cannot be interrupted, return a safe timeout on a live response, suppress late completion, retain the busy gate only during owned cleanup, and test this path. No automatic retries or retained attribution cache. Retry rechecks everything.

### Picker, lifecycle and visual specification

- **Placement:** Add an optional project-only header action to `FilesView`, after the file name; use existing toolbar typography, button border, hover and focus tokens. **Line attribution** is a real disclosure button with `aria-expanded` and `aria-controls`; decorative history icon 14 px. If the host marked text ineligible, disclosure still opens to a read-only explanation; no interactive picker is shown. Granted files, no selection, file read errors, unsupported hosts, and rendered/edit views have no action. During refresh, close the old inspector; expose it only on the newly accepted read.
- **Inspector:** Inline under the header and above the existing preview scroller, not an overlay or new pane. Surface token `--surface`, 1 px `--border` separator, content inset `--files-inset`, 8 px gaps, existing focus ring and accent tokens. Use a visible label **Line**, an approximately 7ch numeric-text field (`inputMode="numeric"`, strict digits), **Look up**, and instruction “Choose a line in the preview or enter its number.” Existing controls retain their hit targets; new controls are at least 32 px high (minimum 24 × 24 CSS px interactive area). Use wrapping flex/grid with `min-width: 0`, inspector text wrapping and independently horizontal-scrolling code. At a 320 CSS px Files pane the controls and result stack/wrap without making the outer pane horizontally scroll; on a wide pane they share one row. Use existing Files container rules, not viewport breakpoints.
- **Selection:** Open focuses the Line field (prefilled first line, or the current fresh search match if available). Click a row only while in pick mode; map pointer Y to a logical row inside the unwrapped monospace `pre` (subtract top padding from its current rect; use computed line height, reject outside text row area). Use the same LF/CRLF source model as the host. Ignore drags/text selections, secondary buttons and events outside source. Do not add thousands of nodes; render only the existing search mark plus a selected-row highlight (preserve exact source selection/copy; reuse the same mark for overlaps). Keep normal text selection and code horizontal scrolling. The field supports keyboard-only selection; Enter submits a valid 1-based number, optionally revealing the selected row inside the preview without moving page or focus. An invalid field shows “Enter a line from 1 to N.” and never sends; on any changed selection clear and abort previous attribution immediately.
- **Result:** `Line 12` header and monospace 8-character SHA chip, **Copy SHA** via `CopyButton` with full SHA and “Copied” announcement, then author and a semantic `time` displaying `YYYY-MM-DD UTC`, then subject as plain text on the next row. Wrap long text, provide selectable full SHA in the inspector (e.g. a focusable read-only field on copy failure), no navigation. Use subdued labels but text contrast at least 4.5:1 and control/focus contrast at least 3:1. Selected row uses `--accent-bg` and inset `--accent-fg` with the Line field/status identifying selection without color alone. Preserve the Search match marker and legend distinctly. Use a polite atomic status for loading/outcome; avoid duplicate live regions. Break long words in the inspector, not the code.
- **Motion/focus:** Disclosure and outcome insertion lay out immediately; one 120 ms opacity-only ease-out fade on the inspector's first appearance/outcome change, from 0 to 1. Do not animate height, scroll, source selection or result removal; no looping spinner or shimmer. Use static “Looking up line N…” and `aria-busy` on the outcome container (announce via a live region outside the busy subtree). Under reduced motion use no transitions. Preserve focus on submit/retry/copy while their states change; if a focused outcome action must disappear, restore to Line or the surviving trigger. Escape inside the inspector or active preview selection closes it, aborts, and restores the trigger only if still mounted; do not intercept Escape on other surfaces. On navigation use the normal Files focus handoff, not forced restoration to the previous file.
- **Request fence:** Use a monotonically increasing generation plus AbortController. Capture owner/base+query, accepted file read generation, path, SHA, proof, selected line and lookup attempt. Invalidate synchronously at navigation, refresh start (including same path or Search reselection), input changes, close and retries. Also fence on committed layout-effect ownership for active/hidden/unmounted or rebound surfaces (see `useFilesRead`); do not update refs from speculative render. Gate both result/error commits and rendering of any retained state on the complete matching identity. Reopen starts idle. When hidden or inactive, clear selection and data even if Files stays mounted. A lookup pending with unchanged line coalesces repeat submits; retry gets a new generation. No Git before submit, and no reload of source when a result arrives.

| State | Copy and action |
| --- | --- |
| Idle / selected | “Choose a line in the preview or enter its number.” Show Line and Look up. |
| Pending | “Looking up line N…” Existing preview stays in place; line entry, disclosure and navigation can cancel. |
| Attributed | Line, short SHA, author, UTC date, subject, Copy SHA. No focus jump. |
| `stale` | “This preview is out of date. Refresh it before looking up a line.” **Refresh preview** uses the normal file refresh and invalidates selection. |
| `changed` | “This file differs from HEAD. Attribution is only available for an exact checked-in version.” No retry loop. Refresh after an external change. |
| `untracked` | “This path is not tracked at HEAD.” Same for new staged files or a directory/symlink/submodule entry at the pin. |
| `binary` / `unsupported_text` / `empty` / `preview_limit` | Respectively: “Binary files do not have line attribution.” / “Attribution requires UTF-8 text with LF or CRLF line endings.” / “This file has no lines to look up.” / “This preview is too large for line attribution.” |
| `history_unavailable` | “This checkout does not have usable local Git history.” No fetch or recovery action that changes the repo. |
| `line_unavailable` | “That line is not available in this preview.” Recheck the field; no automatic shift. |
| `busy` / `timeout` / safe transient error | “Line attribution is busy.” / “The line lookup timed out.” / “Could not look up this line.” **Retry** while the same preview and selection are valid. |
| Revoked / unauthorized | “This project or working copy is no longer available.” Clear data; use normal connect/navigation recovery, never reveal existence to an unauthorized caller. |

No migration: response is additive, proof is ephemeral, and the operation writes no source/index/refs. Roll back by removing the optional control and route together (or with the UI first); the old preview remains usable. No new runtime switch or telemetry stream; reuse normal sanitized host error reporting.
